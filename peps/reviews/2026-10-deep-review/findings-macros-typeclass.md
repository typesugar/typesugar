# Findings: macros-typeclass (typeclass/summon/specialize/auto-derive)

(Transcribed from reviewer report. Repros: review/tc/, run against built packages/{macros,transformer-core,transformer}/dist; several execute transpiled output.)

Why inliner bugs (#1-#4) reach ordinary code: transformer-core tryInlineDerivedInstanceCall / tryAutoSpecialize accept any object literal with an @impl tag OR a PascalCase generic type annotation (hasTypeclassTypeAnnotation, instance-extraction.ts:119), so `const store: Store<number> = {...}` qualifies without opt-in.

1. CRITICAL confirmed — specialize.ts:828-854 substituteParams (from inlineFromNode :707) replaces every Identifier with param's text: property-access names, property-assignment/shorthand names, nested arrow params, local const names; missing arg leaves param free; defaults ignored; spread substituted as ...x. eqPoint.equals(p1,p2) with (x,y)=>x.x===y.x -> p1.p1===p2.p1 (silent wrong); geo.area({w:2,h:3}) -> SyntaxError; (fa,f)=>fa.map((fa)=>f(fa)) -> xs.map(xs=>g(xs)); {f(a,b){const t=a+1;return t*b}} with (q,t) -> t*t; (a,b)=>a+b with one arg -> s+b. Fix: substitute only identifiers resolving to the method's own param decls (checker/scope walk); skip property/binding/shorthand names (expand shorthand to name: arg); refuse to inline on missing/spread/defaulted args; rename body locals hygienically.
2. CRITICAL confirmed — instance-extraction.ts:451-510 isSafeToInlineMethod has no ThisKeyword check; specialize.ts:389-408. Method bodies with `this` inlined; eliminateDeadDerivedInstances deletes the object. `store.get()` -> `this.state` + store deleted -> runtime TypeError; `notEquals(a,b){return !this.equals(a,b)}`. Fix: treat this/super/arguments/new.target (outside nested ordinary functions) as unsafe in isSafeToInlineMethod and hasOnlySafeFreeIdentifiers.
