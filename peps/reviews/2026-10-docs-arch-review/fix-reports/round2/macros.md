## Report: macros group (packages/macros, typesugar, derive, erased)

Five of the seven findings are fixed and two need changes in files owned by other agents (exact changes below). The dists for macros, typesugar, derive and erased are rebuilt. The tests I added pass, and the existing tests I ran pass: the macros resolver, scanner, derive, typeclass, hkt, implicits and comptime tests, the erased tests, the typesugar runtime-bundle test, and the std pep052 and transformer pipeline/implicit tests. One root test now fails because of the Builder removal; see "Left failing" at the end.

### Per finding

1. **C#6 `summon<Functor<Array>>()` picked the Option instance: fixed.** Tests: `packages/macros/tests/summon-docs-review.test.ts` (C#6 block, runs the real pipeline and executes the output).
   - **Cause:** a bare generic type such as `Array` makes `getTypeFromTypeNode` return the checker's error type, which is `any`. `any` is assignable both ways to every type, so it matched whichever instance was scanned first. `Functor<Option>` only worked by the same accident.
   - **Fix:** `summonTargetType` in typeclass.ts uses the symbol's declared type for a bare type constructor, which is the same type the scanner records for `@impl Functor<Option>`. `isTypeMatch` in instance-resolver.ts now refuses to match `any` against a non-`any` instance.
   - **Docs should say:** with no Array instance, `summon<Functor<Array>>()` is a TS9001 compile error. If you declare `/** @impl Functor<Array> */ const arrayFunctor = { map: (fa, f) => fa.map(f) }`, it resolves and prints `[2, 4, 6]`. `Functor<Option>` still works.
2. **S#12 Builder marker: fixed by removing it (breaking change).** It is gone from `macros/src/derive.ts`, the macros index, `runtime-stubs.ts`, `typesugar/src/derive-markers.ts`, `typesugar/src/index.ts` and `derive/src/index.ts`, and the Builder sections are cut from `packages/derive/examples/*.ts`. Test: `packages/derive/tests/exports.test.ts` › "does not export the Builder marker". **Docs should** drop Builder everywhere.
3. **A#8 `@deriving(Eq)`: deferred, needs transformer-core.** Reproduced: the decorator form generates nothing and gives no diagnostic. The JSDoc `/** @deriving Eq */` form already works but gives no warning. Both dispatch points live in transformer-core; see "Needs from other owners".
4. **A#8 Json `fromJson({})` accepted missing fields: fixed.** Tests: `packages/macros/src/json-derive-required.test.ts`, 8 tests with strict on and off.
   - A missing required field now throws `Missing required field <name>`.
   - Optional fields (`x?:`, or a type that admits `undefined`) may be absent. Fields that are present are still type-checked.
   - Optionality comes from the checker mirror, so I added it to the disk-cache key and bumped `DERIVATION_OUTPUT_FORMAT` to 3, so stale cached derivations are not reused.
   - **Returning a plain object for classes is unchanged.** I judged it intended because the derive is structural and Clone does the same.
   - **Docs should say:** `fromJson` validates required fields and their types, and returns a plain object, not a class instance.
5. **comptime fs project root: fixed.** Tests: `packages/macros/src/comptime-sandbox.test.ts` › "comptime fs project root is the project (tsconfig) directory, not the cwd" (3 tests; 2 failed before the fix). The root is now worked out in this order:
   1. the directory of `compilerOptions.configFilePath`;
   2. otherwise the nearest `tsconfig.json` at or above the source file;
   3. otherwise the program's current directory, unless that is "/";
   4. otherwise the source file's own directory.
   - **Docs should say:** fs access is confined to the project (tsconfig) directory, whatever directory the build runs from.
6. **C#5 / A#8 `= summon<Show<A>>()` gave a bare TS9001: fixed.** Test: `packages/macros/tests/summon-docs-review.test.ts` (C#5 block). When the type argument is an in-scope type parameter, TS9001 now adds a note that `A` is a type parameter and a help line: "use `= implicit()` instead … `S: Show<A> = implicit()`". This also covers the `deduplicate` example from A#8. **Docs should** show only the `= implicit()` form.
7. **B#19 `erased<[Show, Eq]>(p)` with `@derive`: fixed.** Test: `packages/erased/tests/macro-execution.test.ts` › "resolves the companions generated by @derive(Show, Eq) on an interface" (failed before the fix, passes now).
   - **Cause:** the transformer, using the ESM copy of macros, records the same-pass `@derive` companions in its `instanceScanner`. `@typesugar/erased` is loaded through the CJS macro loader, which has a separate copy of the scanner that never saw them.
   - **Fix:** `instanceScanner` is now a globalThis singleton (instance-scanner.ts), the same pattern `globalRegistry` already uses.
   - **Result:** the doc examples erased3 and erased4 now run and print `Point(x = 1, y = 2) true`.
   - **Remaining:** `strictOutput` still warns that `Erased<readonly Capability<string>[]>` is not assignable to `WithShow`/`WithEq`, because the emitted `eraseWith(...)` has no capability type argument. I left that alone as out of scope.

### Decisions for Dean

- Builder is removed outright, not implemented. This is a breaking change to the `typesugar`, `@typesugar/derive` and `@typesugar/macros` exports.
- `any` no longer matches non-`any` instances anywhere `resolveInstance` is used. A type that fails to resolve now gives TS9001 or "missing" rather than a wrong instance.
- The comptime fs root is now narrower in one case: running from a monorepo root no longer allows paths outside the package's tsconfig directory.
- `instanceScanner` is now shared through globalThis between the ESM and CJS copies.
- Json `fromJson` keeps returning a plain object for classes (judged intentional).
