## Job

statements. Then re-run EVERY example you touched, and every example the review marked

    node /private/tmp/claude-502/-Users-deapovey-src-personal-typesugar/2c1d0d53-b275-4ae9-af0d-cb3583fec3f8/scratchpad/docrev/doc-example.mjs <file.ts> --run [--under packages/<pkg>]

the real output (trimmed is fine; invented is not).

Rules:

- Fix the doc to match the code. Do NOT change code. If an example still fails because of a
  code bug, rewrite the example to a working form if one exists, otherwise cut it or mark the
  feature "not yet supported" in one line, and list it in your report under "Code bugs still
  open" with the repro.
- Planned/unimplemented features: cut them, or mark them clearly ("Planned — not in 1.0").
  Never describe them in the present tense.
- Where docs show operator or method sugar (`===`, `<`, `+`, `.equals()`, `.clone()`, `.show()`),
  show the PEP-052 activation import it needs (`import "@typesugar/std/syntax/<tc>"` /
  `.../syntax/<tc>/ops`), because without it nothing happens.
- Keep pages' structure and voice; don't rewrite what is correct. No new pages unless your
  prompt says so. Keep VitePress syntax valid (code spans with backticks inside need double

- docs/errors/\*.md are generated by `scripts/generate-error-docs.mjs` from
  packages/core/src/diagnostics.ts; never hand-edit them (except inside their hand-written
  regions, if any).
