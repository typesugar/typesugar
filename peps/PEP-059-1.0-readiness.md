# PEP-059: 1.0 Readiness — Deep Review Outcome and the Road to 1.0

**Status:** Draft (2026-10-19) — review fixes implemented on branch `deep-review-1.0`; the 1.0 task list below is proposed, not started.
**Date:** 2026-10-19
**Author:** Claude (with Dean Povey)
**Depends on:** [PEP-058](PEP-058-production-release-readiness.md) (release pipeline, 0.2.0), [PEP-048](PEP-048-package-triage.md) (package triage)

## Context

PEP-058 made typesugar _releasable_. This PEP asks whether it is _1.0_: would a
stranger who adopts it from npm get correct output, honest errors and a stable API?

To answer that, nine reviewers read every package line by line on 2026-10-18/19
(scopes: core + transformer-core; transformer + integrations; typeclass/specialize;
the other macros; fp; std + collections; effect/contracts/validate/codec; the
math/sql/graph/fusion/mapper/parser/type-system libraries; and tooling/IDE/release).
Each finding had to name a location and a concrete failure, and most were reproduced
against the built `dist`. The full findings, briefs and repro scripts are recorded in
[`peps/reviews/2026-10-deep-review/`](reviews/2026-10-deep-review/README.md).

**309 findings**: 26 critical, 96 high, 121 medium, 66 low (as recorded in the findings
files). The through-line matches
PEP-058's lesson ("verify against the built artifact"), one level deeper: **most macro
tests asserted on the _text_ of generated code and never ran it.** Generated code that
was a SyntaxError, referenced an unimported name, evaluated an argument twice or
returned the wrong value passed those tests. Every fix below landed with a test that
_executes_ the output (or calls the real runtime) and was seen failing first.

## What the review found (the shape of it)

| Theme                                             | Representative findings                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **Security**                                      | `comptime` vm sandbox escapable to host `process` (also in the LSP on repo open); the public playground `/api/run` was remote code execution                                                                                                                                                                         |

### Breaking or visible behaviour changes (need a changeset each, and Dean's sign-off)

These were the conservative choice in each case ("diagnose or throw instead of silently
wrong"), but users will notice them:

- **Diagnostics that used to be hidden are now reported**: Newtype brand mismatches and
  implicit `Base → Newtype` assignment (use `wrap()`); non-`@op` operator errors; errors
  inside non-typesugar `match()` chains.
- **Things that used to compile to wrong code are now compile errors**: unsupported
  `@tailrec` shapes, `let:` guards on non-iterable types, steps after the last bind in
  `let:` without `yield:`, expression-position `par:` (TS9226), unparseable `cfg()`
  conditions, `@contract` on generators, unsupported `validate`/`is<T>()` types,
  `parseStatements`/`parseExpression` on malformed input.
- **CLI**: `build`/`check`/`watch`/`run` exit non-zero on macro errors; `run` refuses to
  execute; `createPipeline` throws on tsconfig errors.
- **Umbrella `typesugar` root is runtime-only** — authoring APIs move to `typesugar/core`.
- **fp**: `List.tail/init/traverse/sequence` return `List | undefined`; stricter
  `traverseFilter`/`mfilter`/`productN`; `./effect` export, `For`, and the Option chain
  macro removed; `ordNumber` is a total order (NaN last), `eqNumber` stays `===`.
- **sql**: default placeholder is Postgres `$n` everywhere; identifiers validated;
  `@derive(Meta)` produces a `<T>Meta` codec; `setTyped`/`Read.make` throw instead of
  guessing.
- **math/units**: non-integer `rat()`, malformed numeric strings and comma-decimal money
  throw; `rationalToBigDecimal` rounds HALF_EVEN; `units` fallback typed `Unit<any>`.
- **type-system**: macros only expand when imported from `@typesugar/type-system`;
  `createStateMachine` needs `states`; `opaqueModule<Repr, Brand>`; `refine` macro removed.
- **graph**: `topoSort`/`isDAG`/`detectCycles` throw on undirected graphs.
- **std runtime**: record helpers return null-prototype objects; `formatDate` is local
  time; `toHex(-1)` is `"-1"`; base64 is UTF-8.
- **contracts**: typed `PreconditionError`/`PostconditionError`/`InvariantError`; prover
  far more conservative and marked experimental.
- **ESLint plugin**: ESLint ≥ 9 (flat config) only.
- **Playground**: `/api/run` disabled; `/api/compile` runs with comptime off.
- **TypeScript peer range** capped at `<6.0.0` (TS 7 has no JS API).

## Decisions only Dean can make

1. **DNS**: typesugar.org serves a Squarespace "Coming Soon" page — every diagnostic help
   URL and `llms.txt` link is dead. Point it at Vercel (the release smoke test now fails
   until this is done).
2. **Editor architecture**: the VS Code extension runs both the LSP server and the
   tsserver plugin, duplicating completion/hover/rename. Pick one engine (or make the LSP
   diagnostics-only).
3. **Package tiers for 1.0**: PEP-048 READMEs say math/units/parser/strings/erased/lsp-server
   are "frozen / excluded from release", but they are published. Every package description
   starts with the 🧊 glyph the READMEs use as the "Frozen" badge.
4. **Comptime trust model**: node:vm hardening closes the known escapes, but vm is not a
   security boundary. 1.0 needs either a real isolate or an explicit "comptime runs with
   build privileges; only build code you trust" contract (current docs say the latter).
5. **`engines`**: raise to `>=20.16` (config loading needs `process.getBuiltinModule`).
6. **Lockstep versioning at 1.0** (deferred by PEP-058).

## The 1.0 task list (proposed)

Ordered by what blocks a credible 1.0. Each item is a candidate wave.

### P0 — blocks 1.0

1. **Ship what's here.** Merge this branch, write the changesets for the breaking list
   above, then PEP-058 Wave 3 (0.2.0 publish, credentials) and Wave 9 (verify the
   published artifacts with `scripts/release-smoke.mjs`).
2. **Per-program state isolation.** Process-global singletons survive across programs in
   watch mode and the LSP: `globalHygiene`, `globalExpansionTracker`,
   `globalResolutionScope`, the diagnostic-suppression rule list, the type-rewrite
   registry, `kindParamRegistry`, the generic registries, effect's layer registries, the
   syntax-marker fallback, the import-suggestion index. This review fixed the
   _correctness_ symptoms one by one (symbol scoping, per-file keys, declaration-keyed
   registries); 1.0 needs one per-Program context object that all of them hang off, and a
   documented reset contract for hosts.
3. **Same-project ordering.** A file that consumes a same-project `@opaque` (or other
   synthesized declaration) and is transformed before the defining file sees no entry.
   Needs a pipeline pre-scan, and a test that permutes transform order for every
   registry-backed macro.
4. **Declaration output.** `.d.ts` is emitted from the pre-expansion AST (no
   `afterDeclarations`), so `@derive` companions and generated members are probably
   missing from published types. Verify with a test; fix if so.
5. **Public API surface.** Mark or remove: core's mutable internals exported without
   stability marking (`standaloneExtensionRegistry`, `globalCoherenceChecker`,
   `globalHygiene`, `MacroExpansionCache`, `profiler`); dead features that look real
   (`prelude.ts`, `manifest.ts`, `MacroPipeline`, `ResolutionTracer`, the unused
   transitive-derivation functions in typeclass.ts, 8 dead modules in vscode/src);
   `coherence`/`capabilities` (now `@experimental`). Then generate an API report
   (api-extractor or the planned typedoc) and freeze it.
6. **Stability tiers in the packages themselves.** Resolve decision 3, then put the tier
   in each package.json/README, and mark experimental: contracts prover, `@compiled`,
   `@fused`, `specializeSchema`, syntax-macro, `transformCode({ strictOutput })`, the
   unplugin `strict` options, and anything else whose README promises more than it does.
7. **Platform and TypeScript matrix in CI.** Windows and macOS jobs (path handling was a
   recurring bug class); TypeScript 5.0/5.4/5.8/5.9 (or raise the floor to what's tested).
8. **CLI parity.** `build`/`watch` don't run the expression-position comprehension
   preprocessing and don't map diagnostics through the HKT source map; no project
   references / `--build` / incremental.
9. **Test convention: execute generated code.** Make "a macro test must run its output"
   the documented rule (and consider a lint check for tests that only assert on printed
   text). Several remaining packages still have string-only macro tests.

### P1 — should be in 1.0

10. **One set of primitive instances.** `macros/primitives.ts` and std's typeclasses both
    define `eqNumber`/`hashString`/… with different semantics (e.g. `hashString`).
11. **Comptime**: `ComptimePermissions.net`/`time` are parsed but unimplemented; included
    files aren't registered as build dependencies (`getFileDependencies` unused), so
    editing an included file doesn't rebuild.
12. **Generic derivation** for `Box<T>`-style types, and remove or finish transitive
    derivation.
13. **fp**: `tailRecM`, a real fiber/cancellation model or an honest scope statement,
    namespace-object root exports (`Console.Console.putStrLn`), monad transformers
    advertised but absent.
14. **sql**: `@schema` is a no-op; two parallel typeclass APIs and two Transactor shapes;
    "parallel" combinators are sequential.
15. **graph/fusion/parser**: O(V·E) successor scans; fusion only fuses map/filter/take;
    `Grammar<T>` results untyped.
16. **Docs as tests.** Compile-check docs snippets in CI (deferred by PEP-058); this
    review found a dozen pages documenting APIs that no longer existed.
17. **Performance**: `offsetToLineColumn` is a linear scan per call (LSP-scale cost);
    keep the weekly benchmark and add a regression threshold.
18. **`resolveModuleSpecifier`** maps any `/packages/<x>/` path to `@typesugar/<x>`, so a
    user monorepo's own `packages/foo` is treated as a macro module.

### P2 — after 1.0

PEP-022 (`/*#__PURE__*/`), PEP-037 (editor integration testing), PEP-040–046 (new
product features), the remaining TODO.md language features.
